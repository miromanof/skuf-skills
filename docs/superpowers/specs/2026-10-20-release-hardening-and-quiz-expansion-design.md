# Skuf Skills: расширение теста и релизное усиление

## Цель

Подготовить `skufskills.ru` к публичной демонстрации: сделать средний уровень теста разнообразным и действительно проверяющим знание контекста, усилить защиту веб-интерфейса и API без смены хостинга, а затем провести воспроизводимую приёмку опубликованной версии внутри браузера Codex.

## Границы

- Сохраняются GitHub Pages для веб-интерфейса и Cloudflare Worker/D1 для API.
- Не добавляется новый reverse proxy и не меняется DNS-маршрутизация.
- Лёгкий и сложный уровни сохраняют текущую механику; средний уровень расширяется до всех встроенных терминов словаря.
- В одном прохождении остаётся 10 вопросов; при повторном прохождении выбирается новая случайная десятка.
- Публичная форма, словарь, админка и существующие опубликованные карточки должны продолжить работать.

## Средний уровень

### Источник терминов

Средний банк должен охватывать каждый встроенный термин из раздела «Словарь», включая русские и англоязычные формы. Мемы из «Мемологии» в этот банк не входят. У каждого термина должен быть ровно один вопрос среднего уровня.

Чтобы список словаря и тест не расходились, встроенные словарные карточки переносятся из `App.tsx` в отдельный экспортируемый модуль данных. Тест строит проверку покрытия по этому источнику.

### Конструкция вопроса

- Формулировка: «Где слово … использовано правильно?»
- Все четыре варианта содержат проверяемый термин или его корректную грамматическую форму.
- Все варианты являются естественными законченными предложениями.
- Правильный ответ использует термин в точном современном значении.
- Неправильные ответы выглядят правдоподобно, но путают значение, оттенок или ситуацию; абсурдные предметные действия и явные определения другого термина не используются.
- Положение правильного ответа перемешивается.
- Варианты внутри одного вопроса уникальны.

### Повторное прохождение

Банк среднего уровня должен содержать больше 10 вопросов. `selectQuestions('medium', 10)` выбирает 10 уникальных вопросов и перемешивает их. Два прохождения при разных источниках случайности должны иметь возможность выдавать разные наборы, а не только разный порядок одной и той же десятки.

## Защита веб-интерфейса

В `index.html` добавляются доступные на статическом хостинге политики:

- Content Security Policy через `meta http-equiv`, разрешающая только собственные скрипты и стили, API `https://api.skufskills.ru`, необходимые изображения и HTTPS-фреймы RuTube/YouTube;
- `Referrer-Policy` через `<meta name="referrer">`;
- запрет устаревших плагинов через `object-src 'none'`;
- ограничение `base-uri` и отправки форм.

Политика не должна блокировать Vite-бандл, API, превью видео, карточки с внешними изображениями или локальную разработку. Директивы, которые браузер не поддерживает в meta CSP (`frame-ancestors`) и заголовки `X-Content-Type-Options`/`Permissions-Policy`, не выдаются за реализованные: для них добавляется точная инструкция Cloudflare Response Header Transform Rule в документацию развёртывания.

## Защита API

Существующие гарантии сохраняются и закрепляются тестами:

- CORS только для перечисленных production/preview/local origins;
- админские маршруты требуют допустимый Origin и активную сессию;
- изменяющие операции требуют CSRF-токен;
- cookies остаются `Secure`, `HttpOnly` для сессии и `SameSite=Lax`;
- логин и анонимные отправки ограничены по частоте;
- размер тела и длины полей ограничены;
- повторная отправка с одним idempotency key безопасна;
- пользовательский HTML остаётся текстом и не исполняется.

Дополнительно API должен возвращать защитные заголовки на всех ответах: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Permissions-Policy` с отключёнными неиспользуемыми возможностями и строгий `Cache-Control` для админских ответов.

## Ошибки и совместимость

- Ошибки формы не должны очищать введённые данные.
- Публичные ошибки не раскрывают внутренние исключения или секреты.
- Поддерживается совместимый idempotency key для iOS без `crypto.randomUUID`.
- Изменения не должны ухудшать ширину около 390 px, клавиатурную навигацию и доступные названия элементов.

## Приёмка

Автоматическая:

- полный `npm test`;
- `npm run typecheck`;
- `npm run build`;
- `npm run check:mobile-css`;
- `npm audit --omit=dev`;
- новые тесты покрытия всех словарных терминов, качества среднего банка и защитных заголовков.

Пользовательская внутри браузера Codex на опубликованной версии:

1. Главная, переключатель 1998 и возврат к современному виду.
2. Поиск «имба» и открытие карточки.
3. Словарь, мемология и внешнее видео без нарушения CSP.
4. Лёгкий, средний и сложный уровни до результата; разбор ошибок и повторный запуск.
5. Форма новой карточки и сохранение данных при ошибке.
6. Проверка появления успешно отправленной тестовой заявки в админке без публикации.
7. Мобильное представление около 390 px: меню, варианты теста, формы и карточки результата.
8. Production-заголовки, CORS, TLS и запрет неавторизованного доступа к админским API.

Тестовая заявка после проверки удаляется либо явно помечается как тестовая и отклоняется.

## Критерий готовности

Работа считается завершённой только после успешной публикации, прохождения всех автоматических проверок и документированного UX-прохода. Нельзя обещать абсолютную неуязвимость; итоговый отчёт перечисляет подтверждённые гарантии, остаточные риски и настройки Cloudflare, которые нельзя обеспечить кодом GitHub Pages.
